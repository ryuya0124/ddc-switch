# Pixio PX243 (Realtek RTK) DDC/CI 入力切替 完全仕様メモ

## 1. 概要と判明した仕様

Pixio PX243（Realtek スケーラーチップ搭載）には、DDC/CI（VCP 0x60）を用いた入力切り替えにおいて以下の固有の挙動・制限が存在します。

### 「-1 オフセット」の法則
モニターのファームウェアは、DDC/CI で受信した設定値（SetVCPFeature）から **内部で -1 されたポート番号に切り替える** 仕様（バグ）となっています。

| 物理ポート | 接続機器 | 手動時の読取値 (Get) | **DDC で送信すべき値 (Set)** | 内部動作 |
| :--- | :--- | :--- | :--- | :--- |
| **DP 1** | （空き） | `15` (0x0F) | **`16`** | 16 - 1 = `15` |
| **DP 2** | （空き） | `16` (0x10) | **`17`** | 17 - 1 = `16` |
| **HDMI 1** | **Mac** | `17` (0x11) | **`18`** | 18 - 1 = `17` |
| **HDMI 2** | **Windows** | `18` (0x12) | **（送信不可）** | `19` はモニターが未対応 |

---

## 2. 現在の接続環境（両方 HDMI）での運用方法

### ① Windows → Mac (HDMI 1) への切り替え
**「リレー切り替え（一度 DP を挟む）」が必須** です。

```powershell
ddc switch 16; ddc switch 18
```

#### なぜリレーが必要なのか？
1. Windows（HDMI 2）表示中のモニターの現在値は **`18`**。
2. Mac（HDMI 1）へ切り替えるために送信すべき値も **`18`**。
3. Windows にいる状態で直接 `18` を送ろうとすると、`ddc-switch` ツールが「現在値(18)と要求値(18)が同じ（すでにその入力にいる）」と判定して送信をスキップ（`Already on ...`）してしまいます。
4. 先に `ddc switch 16` で一度 DP（15）へ逃がすことで現在値が変わり、直後の `ddc switch 18` が正常に送信されて Mac（17）へ切り替わります。

### ② Mac → Windows (HDMI 2) への復帰
* **Windows 側からの DDC コマンドでは復帰不可**:
  * 理論上は `19` を送る必要がありますが、モニターが `19` を受け付けないため、ソフトウェアから HDMI 2（18）を指定して戻すことはできません。
* **復帰方法**:
  * モニター背面のジョイスティック（ボタン）を操作して **手動で「HDMI 2」に戻す** 必要があります。

### ③ DP 2 への切り替え
* 以下のコマンドで DP 2（16）に切り替え可能です：
```powershell
ddc switch 17
```

---

## 3. 推奨改善案（Mac を DisplayPort 接続にする）

空いている **DP 2 ポート** を活用し、Mac を **「USB-C → DisplayPort ケーブル」** で接続することで、上記の問題がすべて解消されます。

* **Windows → Mac の切り替えが一発で可能（リレー不要）**:
  * `ddc switch 17` を送るだけで、一撃で **DP 2 (16 / Mac)** に切り替わります。
* **Mac 側の DDC 制御も安定**:
  * Apple Silicon Mac の「HDMI からの DDC 信号遮断」問題も回避できます。

## 4. クイック実行コマンドまとめ

| 行いたい操作 | 実行コマンド |
| :--- | :--- |
| **Mac (HDMI 1) へ切り替え** | `ddc switch 16; ddc switch 18` |
| **DP 2 へ切り替え** | `ddc switch 17` |
| **DP 1 へ切り替え** | `ddc switch 16` |
| **Windows (HDMI 2) へ戻す** | モニター背面のボタンで手動切替 |
